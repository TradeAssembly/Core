# Public workspace portability and descriptive results

Core owns these interfaces without Hub, Relay, hosted billing, or Warden migration dependencies. The actual local CLI verifies its existing identity and requires the local runtime profile and SQLite storage. A verified provider identity may export or import its own local records through that CLI; it does not acquire records belonging to the standalone local owner. Direct provider service calls and HTTP/MCP portability mutation remain unavailable. Standalone Core requires no hosted account.

```sh
tradeassembly --db SOURCE_DB workspace export --out NEW_BUNDLE_FILE
tradeassembly --db EMPTY_TARGET_DB workspace import --from BUNDLE_FILE
tradeassembly --db SOURCE_DB workspace export --stdout
tradeassembly --db EMPTY_TARGET_DB workspace import --stdin
tradeassembly --db WORKSPACE_DB result-summary --strategy-id STRATEGY_ID
```

CLI responses retain the normal envelope. With `--stdout`, `.data` is the `tradeassembly.public-workspace.v1` bundle. Import stdin accepts that bundle JSON, without the CLI envelope. A companion can encrypt stdout in memory and pass decrypted bundle bytes directly to stdin without writing plaintext files. File export never overwrites. Unix file operations open each ancestor with `NOFOLLOW` and use directory descriptors; parent traversal, symlink ancestors, symlink inputs, and nonregular inputs fail. Use canonical paths (macOS `/var` and `/tmp` are system symlink aliases). File I/O on non-Unix hosts and unsupported storage adapters fail explicitly.

The bundle is bounded to 16 MiB, 4096 entries, 2 MiB per entry, and 48 payload levels. Schema and collection version, record checksums, bundle checksum, unique identifiers, closed field allowlists, typed reports/configurations/notebooks, and cross-record references are validated before mutation. Entry keys are identifiers, never filesystem members. No extraction or caller-selected destination paths are stored. These SHA-256 checks establish integrity, not a sender signature or ownership delegation.

Included collections:

- Stored strategy definitions, immutable versions, and drafts. No synthetic installation examples are materialized for backup. Definitions restore with status `stopped`; capability bindings are cleared.
- Real stored research notebooks and universe configuration. Notebook exports are regenerated from their typed contracts; source replay pointers are marked unavailable in the target workspace.
- Dataset metadata, content digests, source provenance, snapshot references, and local research dataset configuration. Raw provider or local dataset observations are excluded. Metadata restores to `public_dataset_references_v1`; it does not impersonate an available raw dataset.
- Native `backtest_runs_v2` completed configurations and verified reports from `backtest_report.rs`. Completed report, trade, journal, order, fill, position, and ledger artifacts restore to `public_backtest_reports_v1`; configuration restores to `public_backtest_configurations_v1`. Raw chart bars are excluded. Original report hashes remain source provenance; entry/bundle digests bind the portable artifacts. Restored reports are read-only artifacts surfaced by result summaries, without recreating runnable jobs or claiming replay availability.

No durable safe workspace settings namespace currently exists. `settings` explicitly says `not_supported_no_durable_settings_namespace`. Legacy synchronous `backtests` records are unsupported; `legacyBacktestsExcluded` records their exact stored count. This export is public research portability, not a complete machine or journal backup. Credentials, tokens, private keys, broker account state, raw datasets, active execution configuration/authority, worker queues/leases, local owner identity, and policy service state are excluded.

Import requires an empty durable workspace. The exact eight ownership scopes seeded by authenticated local startup are permissible bootstrap metadata; unrelated scopes, data, or execution work fail the check. Import rebinds objects to the target local owner. SQLite checks emptiness and writes every safe record plus the digest-bound receipt in one `BEGIN IMMEDIATE` transaction with FULL synchronous WAL. A failed write rolls back all imported records. Retrying the same bundle succeeds only while all imported records and permissible bootstrap scopes still exactly match; modified state fails closed. Existing workspaces are never merged or overwritten. No activation, scheduler work, broker order, or execution authority is restored.

`tradeassembly.strategy-result-summary.v1` separates operational run state, paper execution accounting, and native completed backtests. Native metrics come from integrity-verified `backtest_report.rs` calculations; archived portable reports use their validated accounting overview. Gross and net P&L, actual fees, reconciliation residual/status, time coverage, immutable strategy/dataset provenance, and source report digest are reported separately. Backtests are not summed into paper performance.

Operational and paper `reconciliationStatus` preserves the execution ledger state: `clear`, `required`, or `unavailable`. Clear means no pending reconciliation requirement; it does not imply complete accounting or independently observed provider reconciliation.

Paper metrics use the existing `tradeassembly.execution_ledger.v2` calculation for each actual activation. Missing price or realized P&L evidence remains null/unavailable. Paper fees are unavailable until that accounting owner supplies them. Each run carries actual durable start/stop milliseconds converted to RFC3339, snapshot provenance, and completeness. The source digest binds the operational, paper, backtest, and cursor projections. `source.localArchiveCursor` is the actual latest integrity-verified durable journal sequence for the authenticated owner, with its record digest; it is null when no owned event exists. It is not an event count or a synthetic zero. Legacy journal export schema v1 is unchanged.

The closed wire schemas are `contracts/public-workspace.v1.schema.json` and `contracts/strategy-result-summary.v1.schema.json`. Core runtime validation additionally checks semantics and byte bounds. Targeted tests cover durable roundtrip, stopped restore, ownership, unchanged retries, malformed/tampered/oversized/sensitive/traversal/symlink rejection, an injected second-write rollback followed by restart/retry, a killed child holding the actual SQLite import transaction followed by clean recovery/retry, actual engine P&L/fees/reconciliation preservation, owner journal cursors, and preassigned MCP activation/configuration IDs with one bounded local paper tick. These are local engineering evidence, not provider deployment or production trading acceptance.

Broker status exposes `instances[].credentialStatus.authenticationMethod` as `api-key`, `oauth`, or `unavailable`. Core derives this from the validated accepted credential map and binds its non-secret metadata to the credential generation. It invalidates the prior generation before replacing the credential map, so interrupted metadata writes cannot report the old method as current. Missing legacy provenance, revoked credentials, and stale generations remain unavailable. This field proves credential type, while account verification and observed provider orders remain separate evidence. It does not expose credential values or claim an OAuth browser flow merely from a requested label.
